## 코드 리뷰에서 남긴 것

2026-11-15 전체 코드 리뷰에서 나왔고 아직 고치지 않은 것. 경위는 [decisions.md](decisions.md) "배포 전 코드 리뷰에서 고친 것".

- [ ] 확장이 업데이트되면 열려 있던 유튜브 탭에 먹통 UI가 남는다. 메뉴 버튼은 눌러도 반응이 없고, 해제해도 가려진 채다(새로 고치면 풀린다). 끊길 때 우리가 붙인 것을 떼기만 할지, 새 스크립트를 다시 넣기까지 할지 사용자가 정한다
- [ ] 댓글 정렬을 바꾼 직후 약 160ms 동안 앞 댓글의 가림이 남는다(실측). 차단한 작성자의 댓글이 그 사이에 보일 수 있다. 요소 안이 바뀐 것도 바로 처리하게 하면 되는데, 감시 콜백이 하는 일이 늘어서 재 보고 정한다
- [ ] 접근성. 메뉴를 Esc나 항목 선택으로 닫으면 포커스가 버튼으로 돌아가지 않는다. 가림막 pill과 메뉴 버튼에 키보드 포커스 테두리가 없다. 차단 목록에서 ×로 지우면 포커스가 사라진다. 기간의 "직접"을 고르면 입력칸이 포커스보다 앞에 나타난다. 설정 페이지 탭의 `aria-controls`가 없는 패널을 가리키고 Home·End가 안 된다
- [ ] 직접 입력한 기간이 잘못된 값(소수 등)이면 저장되지 않는데 알려 주는 것이 없다
- 동기화 공간이 넘친 상태에서 두 PC가 서로 모르는 옛 항목을 들고 있으면 같은 sync 키를 번갈아 덮어쓸 수 있다. 1,300명이 넘고 동기화를 꺼 둔 채 따로 쓴 경우에만
- 차단한 시각이 없는 예전 항목끼리 핸들의 대소문자만 다르면 두 PC가 번갈아 덮어쓸 수 있다. 새 항목에는 늘 시각이 있다
- `UC`로 시작하는 24자 핸들을 @ 없이 넣으면 채널 ID로 읽는다
- 첫 사용 안내를 열어 둔 채 다른 창에서 기간을 바꾸면 안내의 "직접" 칸이 옛 값을 보여 준다. 저장된 값과 요약은 맞다

- 차단할 때 흐리게와 "차단된 댓글"로 바꾸기에도 애니메이션. 완전히 숨기기의 접힘과 같은 220ms. "숨긴 항목 보기"·"다시 가리기"와 설정으로 방법을 바꾸는 전환도 움직인다. 차단·해제는 사용자가 실제 유튜브에서, 나머지는 로그아웃 헤드리스 크롬에서 확인했다 (2026-10-06)
- 스캔 스케줄링 실측. 디바운스 150ms를 확정값으로 뒀다. 간격은 0~500ms 어디든 비용이 같았고 디바운스 스캔이 잡은 것은 없었다. rAF와 IntersectionObserver는 쓰지 않는다. 묶음마다 두 번 훑는 것도 둔다. 수치는 [decisions.md](decisions.md) (2026-10-06)
- 차단된 댓글의 메뉴에서 해제와 종류 바꾸기. 걸려 있는 종류의 자리에 "영구 차단 해제"나 "임시 차단 해제"가 나오고, 다른 종류를 누르면 그 종류로 바뀐다. 완전히 숨긴 댓글은 메뉴를 열 수 없어서 전처럼 패널이나 팝업에서 푼다. 로그아웃 헤드리스 크롬에서 확인했다 (2026-10-06)
- 차단 목록 페이지. 목록을 팝업에서 옵션 페이지(탭)로 옮기고, 팝업에는 차단한 수와 "차단 목록 관리" 버튼만 남겼다. 설정은 팝업에 그대로 있다. 손으로 넣는 입력칸은 목록과 함께 페이지로 갔다. 로그아웃 헤드리스 크롬에서 확인했다 (2026-10-06)
- 차단 목록을 영구 차단과 임시 차단 두 묶음으로 나누고 묶음마다 정렬. 최근에 차단한 순(기본), 오래된 순, 이름순, 임시에는 곧 풀리는 순. 고른 정렬은 저장하지 않는다. 로그아웃 헤드리스 크롬에서 확인했다 (2026-10-06)
- 차단 목록 페이지의 입력칸 접기와 쪽 나누기. 손으로 넣는 입력칸은 제목 옆 + 버튼으로 펼치고 접는다(220ms). 묶음은 20개(임시값)씩 쪽으로 나눈다. 로그아웃 헤드리스 크롬에서 확인했다. 움직임이 눈에 어떻게 보이는지는 못 봤다 (2026-10-06)
