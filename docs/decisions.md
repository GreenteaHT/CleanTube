# 설계 결정

큰 결정을 할 때마다 여기에 추가한다. 코드만 보고는 "왜 이렇게 했더라"를 알 수 없는 것들.
형식은 결정, 이유, 재검토 조건. 결정이 뒤집히면 지우지 말고 그 아래에 "뒤집음"과 이유를 적는다.
코드에 있다고 결정은 아니다. 실제로 고민하고 정한 것만 적는다.

## 2026-09 유튜브만, 한 단계씩

- 결정: 대상 사이트는 유튜브로 한정한다. 기능은 한 번에 하나씩, 사용자가 정한 범위만 만든다.
- 이유: 처음 뼈대에 키워드 필터, 영상 카드, 쇼츠, 흐리게 모드까지 한꺼번에 들어가 있었다. 만든 사람이 왜 있는지 모르는 기능은 배우면서 만든다는 목적에 맞지 않아서 걷어냈다. 걷어낸 코드는 첫 커밋(b30868a)에 있다.
- 재검토 조건: 없음. 다른 사이트는 유튜브가 충분히 다듬어진 뒤에나 생각한다.

## 2026-09 1단계는 특정 작성자의 댓글 숨기기

- 결정: 첫 기능은 "@핸들 또는 채널명을 목록에 넣으면 그 사람의 댓글과 답글을 숨긴다". UI는 팝업의 목록 편집 하나.
- 이유: 사용자가 가장 먼저 원한 기능. 댓글 하나에 작성자 하나라 매칭이 단순하고, 화면에서 결과를 바로 확인할 수 있다.
- 재검토 조건: 실제 유튜브에서 확인한 뒤 매칭 규칙(정확 일치, 띄어쓰기 처리)을 확정한다.

## 2026-09 WXT를 쓴다

- 결정: Vite 직접 설정 대신 WXT 프레임워크.
- 이유: 비교 없이 추천으로 선택했다. `entrypoints/` 구조로 manifest를 자동 생성하고, 개발 모드에서 브라우저를 띄워 주고, storage 래퍼가 편하다는 설명을 듣고 동의했다. 지금까지 불편한 점은 없다.
- 재검토 조건: WXT 때문에 막히는 일이 생기면 CRXJS(Vite 플러그인) 등과 비교한다.

## 2026-09 DOM을 지우지 않고 속성만 토글한다

- 결정: 숨길 댓글에 `data-cleantube-blocked` 속성을 붙이고 CSS가 처리한다. `remove()`는 쓰지 않는다.
- 이유: 목록에서 빼면 되돌릴 수 있어야 한다. 유튜브 자체 스크립트가 지워진 요소를 참조하면 깨질 수 있다. 속성 값에 매칭된 항목을 넣어 두면 DevTools에서 왜 숨겨졌는지 바로 보인다.
- 부작용: 숨긴 요소도 DOM에 남는다. 아직 문제는 관찰 안 됨.

## 2026-09 설정 상태는 storage가 단일 진실 원천

- 결정: 설정은 chrome.storage에 두고 팝업과 콘텐츠 스크립트가 각자 구독한다. 백그라운드 메모리에 상태를 두지 않고, 설정 전달에 `runtime.sendMessage`를 쓰지 않는다.
- 이유: 지금 나눌 상태가 설정 하나뿐이다. storage 변경 이벤트는 크롬이 모든 컨텍스트에 알아서 쏘므로 배달 코드가 없고, 새 탭은 storage만 읽으면 되고, 서비스 워커가 잠들어 있어도 동작한다. 그래서 백그라운드 스크립트가 없다.
- 재검토 조건: 배지 카운트나 우클릭 메뉴처럼 "상태"가 아닌 "명령"이 필요해지면 메시징을 추가한다. 그때도 설정은 storage에 남긴다. 둘은 공존한다.

## 2026-09 상태 라이브러리를 쓰지 않는다

- 결정: zustand 같은 상태 라이브러리 없이 `useSettings` 훅과 WXT storage 래퍼만 쓴다.
- 이유: 컨텍스트 간 공유는 storage가 이미 해결한다. zustand는 한 페이지 안의 상태 공유 도구라 여기에 넣으면 storage 위에 층만 하나 는다. 콘텐츠 스크립트는 React가 아니라 도움도 안 된다.
- 재검토 조건: 페이지 안에 저장하지 않는 UI 상태(검색어, 펼침 상태 등)가 많아지면 그 페이지에만 일반 zustand를 넣는다. 설정은 그대로 storage 구독. 백그라운드가 주인인 실시간 공유 상태(탭별 숨긴 개수 등)가 늘어나면 webext-zustand를 검토한다. 작은 커뮤니티 라이브러리라 그 시점의 유지보수 상태를 먼저 확인한다.

## 2026-09 storage.sync 항목 하나에 설정 전체

- 결정: `sync:settings` 키 하나에 Settings 객체를 통째로 넣는다.
- 이유: 읽기와 구독이 한 번으로 끝난다. 크롬 계정 간 동기화가 공짜다.
- 알려진 한계: sync는 항목당 8KB 제한이 있다. 목록이 수백 개가 되면 넘는다. backlog에 있음.

## 2026-09 매칭 로직은 순수 함수로 분리

- 결정: `utils/matcher.ts`는 문자열만 받고 문자열만 돌려준다. DOM, storage, WXT import 금지.
- 이유: 유튜브 DOM 없이 단위 테스트가 가능해야 한다. 대소문자, @ 처리, 띄어쓰기는 버그가 나기 쉬워서 테스트로 고정할 가치가 있다.

## 2026-09 공개 저장소, GPL-3.0

- 결정: 소스를 공개하고 GPL-3.0을 붙인다.
- 이유: 크롬 확장기능은 설치하면 빌드 결과물에서 코드가 보이므로 비공개의 실익이 없다. GPL은 가져다 쓴 결과물도 공개하게 해서 닫힌 상용 제품에 쓰이는 걸 막는다.
- 대안: MIT. 나중에 더 열고 싶으면 바꿀 수 있다. 반대 방향은 이미 배포된 버전에 소급되지 않는다.
